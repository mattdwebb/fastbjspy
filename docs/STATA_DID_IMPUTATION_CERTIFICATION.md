# Official Stata did_imputation certification

**Conditionally certified.** The unchanged official command agrees with Python on all 14 deterministic fixtures and all 112 state deletions when the identical state/year fixed-effect model is represented by explicit dummy controls through documented fe(.) and controls(...) options. No Python estimator was altered to force agreement. The condition concerns numerical representation in the installed Stata dependency, not a changed estimand.

Official source: https://github.com/borusyak/did_imputation at commit `767c8d6670a751170910d419bbafd323df92ef08`, command version November 22, 2023. Installed project-locally and in the standard user ado directory with explicit user permission. Existing reghdfe/ftools packages were not upgraded. StataNow/SE 18.5, reghdfe 5.7.3 (13nov2019), and existing ftools were used. The comparator commit above identifies the upstream source used for this recorded check.

Maximum official scalar discrepancy: **3.652633751016765e-14**. Maximum first-stage/component discrepancy: **2.4202861936828413e-13**. Maximum delete-one-state discrepancy: **2.2093438190040615e-13**. All numerical comparisons pass 1e-9. Aggregation weights and sample inclusion agree. The intercept normalization is aligned by reconstructing the common intercept from official treated predictions and reported dummy/control coefficients; all fitted untreated outcomes and ordinary covariate coefficients are then checked, not just the final scalar.

Fixtures cover balanced panels, repeated cross sections, one and early/late/never cohorts, unequal/extreme sizes, missing cells, ordinary covariates, unbalanced treated-post counts, homogeneous/cohort/state/time-varying/heterogeneous-zero-average effects, and moderate/extreme positive estimation weights. Python's preserved legacy point API handles weighted/missing-cell cases; these checks do not expand the common inference adapter's documented scope.

## Diagnosed default-solver difference

The same official command with fe(state year) and the installed 2019 reghdfe produced small representation/precision differences on ordinary fixtures and a maximum scalar difference of **0.0026715538204779999** on weights ranging from 0.01 to 1000. Stata float intermediates also mattered; input import and generated variables were changed to double precision for certification. Default absorbed-FE results are retained in stata_point_comparisons.csv, not hidden or counted as exact passes. Direct Stata dummy-variable WLS and the official explicit-dummy representation recover the Python value for the extreme-weight case to about 1e-14. The evidence localizes the remaining discrepancy to numerical fixed-effect estimation/recovery in that dependency setup. Tighter reghdfe residual tolerance alone did not remove it. No global dependency update or modification of official code was made.

Use the certified explicit-dummy specification for these deterministic external checks. The default absorbed-FE invocation is not certified at 1e-9 under this installed dependency, especially with extreme weights. This caveat should be revisited with a separately authorized current dependency environment before relying on default Stata weighted fits.

## Jackknife

Official point fits were recomputed after every state deletion. CV3J SE, t, df=G-1 and Student t p-values were constructed from those deletion estimates and agree with the Python recomputation oracle and supported public fast paths. This is not a claim that Stata's native BJS standard-error formula equals CV3J: native inference was disabled with nose. Detailed deletions are in stata_deletion_comparisons.csv. Maximum JK SE/t/p gaps are 6.58e-14, 4.27e-12, and 4.88e-15, respectively.

## Reproduction

Generate the deterministic fixtures with did_certification/fixtures.py, then run tests/stata/certify_explicit_fe.do in Stata and did_certification/certify_stata_results.py in Python. tests/stata/certify.do preserves the default absorbed-FE comparison and diagnose_weights.do isolates the extreme-weight discrepancy. Data, targets, covariates and positive estimation weights are identical across languages; never-treatment is converted from 0 to Stata missing explicitly. Fixed-effect normalization differs only by parameterization and is aligned before coefficient/prediction comparison. No sample trimming or autosample option is used.
